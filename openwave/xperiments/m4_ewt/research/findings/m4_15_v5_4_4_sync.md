## Finding 1 (M4.15): Synchronization of M4 Scripts to Manuscript & Code Record v5.4.4

## Status

DONE (post-hoc)

## Criterion

`Repository sync` — verify consistency between OpenWave M4 scripts and the published v5.4.4 Zenodo code record (`10.5281/zenodo.24525643`). No `MODELS.md` criterion: this is a repository task, not a scorecard row.

**Scope**: compares the M4 scripts in `research/scripts/` with the scripts of the v5.4.4 code record, file by file, after the normalization below. It does not check the manuscript's derivations, the archive's `.txt` outputs, `ewt_robustness_plots.py`, or the repository scripts the archive does not contain (M4.9, M4.10.2, M4.12, M4.16, M4.17, `validate_geometry.py`, `validate_xparameters.py`).

### 1. Scope of Synchronization (v5.3.1 $\rightarrow$ v5.4.4)

Originally queued after [PR #717](https://github.com/openwave-labs/openwave/pull/717) to target v5.3.2, this task was consolidated directly into the **v5.4.4** release (`2026-11-24`) to keep the repository aligned with the active manuscript version (`10.5281/zenodo.24513845`) and its accompanying code record (`10.5281/zenodo.24525643`), as well as the newly added scale-running modules (`M4.16` and `M4.17`):

* **Core Engine (`M4.7`):** Updated `m4_7_ewt_emergence_engine.py` and companion engine scripts to the v5.4.4 geometric definitions, including the vacuum/gravity sector helpers used downstream by `M4.16` and `M4.17`. The line `r_e_geom = 100.0 * nu_result["r_nu"]` predates this sync (it was already on `main`, where it feeds the atomic scales); the engine's gravity path uses the CODATA `R_E`.
* **Cosmological Constant (`M4.14`):** `m4_14_ewt_cosmological_constant.py` brought to the archive's `ewt_cosmological_constant.py`: the header, the import and use of `derive_planck_temperature`, and the printed label "Algebraic identity (tautological by construction)". The formula behind `derive_planck_temperature` is the one the script computed inline, so the numbers do not change.
* **Lock-in Scan (`M4.11`):** not changed. The repository script matches the archive apart from the archive's header line. The Weinberg row's operator and `M_W` anchor, the single Planck set and the sources of the two W-mass labels, carried here from the review of PR #717, moved to the backlog row M4.18.

### 2. Note on File Checksums (SHA-256) and Module Naming

Raw file-level SHA-256 hashes of the OpenWave scripts do **not** match the raw files inside the upstream Zenodo archive (`10.5281/zenodo.24525643`) by design:

1. **Prefix Convention:** OpenWave roadmap standards require all task scripts to carry the `m4_<n>_` prefix (e.g., `m4_7_ewt_emergence_engine.py`), whereas the upstream Zenodo archive distributes standalone scripts without task-ID prefixes.
2. **Cross-Module Imports:** Because scripts in `research/scripts/` import shared helpers directly from `m4_7_ewt_emergence_engine` (e.g., `from m4_7_ewt_emergence_engine import ...`), internal `import` statements differ from the unprefixed Zenodo source files.

Equivalence is therefore checked on normalized text. Normalization: replace CRLF with LF, drop the `m4_<n>_` prefix in front of `ewt_` in module names, and ignore the final newline.
