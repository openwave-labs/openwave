## Status

## Criterion
`Repository sync` — verify consistency between OpenWave M4 scripts and the published v5.4.4 Zenodo code record (`10.5281/zenodo.24525643`)

### 1. Scope of Synchronization (v5.3.1 $\rightarrow$ v5.4.4)

Originally queued after [PR #717](https://github.com/openwave-labs/openwave/pull/717) to target v5.3.2, this task was consolidated directly into the **v5.4.4** release (`2026-11-24`) to keep the repository aligned with the active manuscript version (`10.5281/zenodo.24513845`) and its accompanying code record (`10.5281/zenodo.24525643`), as well as the newly added scale-running modules (`M4.16` and `M4.17`):

* **Core Engine (`M4.7`):** Updated `m4_7_ewt_emergence_engine.py` and companion engine scripts to the v5.4.4 geometric definitions (including `r_e = 100 * r_nu` and the updated vacuum/gravity sector helpers used downstream by `M4.16` and `M4.17`).
* **Lock-in Scan (`M4.11`):** Updated the Weinberg mixing row to use the mixed operator and its $M_W$ anchor, and aligned cosmological targets on a single Planck 2018 reference set.
* **Cosmological Constant (`M4.14`):** Synced `m4_14_ewt_cosmological_constant.py` against the updated v5.4.4 `M4.7` chain.

### 2. Note on File Checksums (SHA-256) and Module Naming

Raw file-level SHA-256 hashes of the OpenWave scripts do **not** match the raw files inside the upstream Zenodo archive (`10.5281/zenodo.24525643`) by design:

1. **Prefix Convention:** OpenWave roadmap standards require all task scripts to carry the `m4_<n>_` prefix (e.g., `m4_7_ewt_emergence_engine.py`), whereas the upstream Zenodo archive distributes standalone scripts without task-ID prefixes.
2. **Cross-Module Imports:** Because scripts in `research/scripts/` import shared helpers directly from `m4_7_ewt_emergence_engine` (e.g., `from m4_7_ewt_emergence_engine import ...`), internal `import` statements differ from the unprefixed Zenodo source files.

Consequently, equivalence with `10.5281/zenodo.24525643` is established at the level of equations, constants, and numerical outputs rather than raw file hashes.
